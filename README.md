# CloudBookmark

把浏览器书签同步到**你自己的 GitHub Gist**——跨浏览器、跨设备，不需要任何服务器。

> 这个项目受到 [dudor/BookmarkHub](https://github.com/dudor/BookmarkHub) 的启发，
> 但你看到的是 **v3 的完整重写**：同步算法换成了带快照的三方合并，
> 修掉了旧版本"删除不同步""书签重复""删不掉"等一批问题，
> 并补上了自动同步、冲突界面、备份回滚、导入导出。
> 具体改了什么见 [docs/08-本次重构改了什么](docs/08-本次重构改了什么.md)。

## 它解决什么问题

| 痛点 | 原生同步 | CloudBookmark |
|------|---------|---------------|
| 跨浏览器（Chrome ↔ Edge ↔ Firefox） | ❌ 只支持同厂商 | ✅ 支持 |
| 数据存在哪 | 厂商服务器 | ✅ 你自己的 GitHub 账号 |
| 需要注册新账号 | 需要 | ✅ 复用已有的 GitHub 账号 |
| 需要服务器/运维 | 不需要 | ✅ 同样为零 |
| 版本历史 | 有限 | ✅ Git 天然支持，可回溯任意版本 |
| 冲突处理 | 黑盒 | ✅ 透明，可以逐条自己决定 |

## 特性

**同步**

- **三方合并**：用"上次同步的样子 + 现在本地 + 现在云端"三份数据算出结果，
  所以"一边新增、一边删除"能被正确区分——这是不丢书签的前提
- **删除可传播**：在一台设备删掉，另一台设备同步后也会删掉
- **字段级合并**：你改标题、另一台改网址 → 两处改动都保住，不会来打扰你
- **只有真冲突才问你**：两边改到同一处才暂停，并列出"上次/本地/云端"三列供你选择
- **首次同步不重复**：新设备按网址自动和云端配对，不会把书签变成两份
- **顺序也会同步**：排序冲突自动合并，不打扰你

**自动化**

- **变更后自动同步**：改完书签约 3 秒自动同步（可关）
- **定时同步**：默认每 15 分钟（可配 5 分钟 ~ 3 小时）
- **状态徽章**：图标上直接显示"同步中 / 有 N 个冲突 / 出错"
- **省接口**：内容没变就不上传；有防抖和最小间隔，不浪费 GitHub 额度

**安全**

- **只请求 `gist` 一个权限**，`host_permissions` 也只声明 `api.github.com` 和 `github.com`
- 支持**两种授权方式**：手动填 Token，或用 GitHub 账号授权（设备流程）
- 凭据加密后存本机，**明文永不落盘**（加密强度的诚实说明见
  [docs/07-常见问题](docs/07-常见问题.md) 第五节）
- Gist 是**私有**（secret）的

**界面**

- **深色模式**：跟随系统 / 强制浅色 / 强制深色 三选一，右上角一键切换
- 小弹窗负责日常操作；独立设置页负责冲突对比、数据管理、历史

**数据管理**

- 导出 / 导入 JSON（合并或替换两种模式）
- 每次覆盖操作前自动备份，可**一键回滚**（本地或云端）
- 重复书签扫描与清理（只在你点击时运行）
- 同步历史 + 书签变更记录

## 安装

### 从源码构建

```bash
git clone https://github.com/Yuuuno224/CloudBookmark.git
cd CloudBookmark
npm install
npm run build
```

### 加载到浏览器

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选择项目里的 **`dist` 目录**

## 使用

1. 点扩展图标 → **设置**
2. 用下面两种方式**任选一种**完成 GitHub 授权
3. 回到弹窗 → 点 **立即同步**

第一次同步会在你的 GitHub 账号下自动创建一个私有 Gist 存放书签数据。
**在其他设备上装好扩展、用同样的方式授权、同步一次**，书签就互通了。

### 授权方式一：填一个 Token（最简单）

1. GitHub → 右上角头像 → Settings → Developer settings
2. Personal access tokens → **Tokens (classic)** → Generate new token
3. **只勾 `gist`**，其它一律不勾
4. 生成后复制粘贴到扩展的设置页 → 点「验证并保存」

（也用细粒度 Token：Personal access tokens → **Fine-grained tokens** →
Account permissions → **Gists** → **Read and write**。注意 "Resource owner"
要选对账号，组织启用 SSO 时还需额外授权。）

### 授权方式二：用 GitHub 账号授权（不用复制长字符串）

1. 先去免费创建一个 OAuth App：
   [github.com/settings/applications/new](https://github.com/settings/applications/new)
   - Application name 随便填，Homepage URL 填 `https://github.com`
   - **务必勾选 "Enable Device Flow"**
2. 把页面上的 **Client ID**（形如 `Iv1.xxxx`）填进扩展的设置页
   → 点「开始授权」
3. 扩展会显示一个 8 位验证码并自动复制，点「打开 GitHub 授权页」粘贴进去、
   点 Authorize，回来就自动登录了

> **为什么这种方式要自己建 OAuth App？**
> 因为"点按钮跳转授权"那种常见做法需要 `client_secret` 才能换到 token，
> 而扩展的代码是公开的，藏不住密钥。GitHub 的**设备流程**专门为没有后端的
> 客户端设计，换 token 只需要公开的 `client_id`（不是密钥，泄露也没关系）。
> 但只有注册这个 App 的人才能拿到 client_id，所以需要你自己花一分钟建一个。
>
> 如果这个项目的作者愿意内置一个共用的 client_id，就可以省掉这一步——
> 但需要作者自己去注册那个 App。

> 为什么只勾一个权限？因为万一凭据泄露，别人也只能读写你的 Gist，
> 动不了你的代码仓库。这是这个项目唯一真正有效的安全措施。

## 四种操作的区别

| 操作 | 对本地书签 | 对云端 | 什么时候用 |
|------|-----------|--------|-----------|
| **合并同步** | 写入合并结果 | 内容有变化时上传 | ✅ 日常就用这个 |
| **上传覆盖** | 不动 | 用本地覆盖 | 云端数据乱了，想强制对齐 |
| **下载覆盖** | 用云端覆盖 | 不动 | 本机数据乱了，想强制对齐 |
| **导入 JSON** | 按你的选择改动 | 不动 | 从备份恢复 |

后三种都是单向覆盖，执行前都会 **二次确认 + 自动备份**。

## 技术栈

| 类别 | 选型 | 为什么 |
|------|------|--------|
| 语言 | TypeScript | 类型检查能在编译期拦住一大批错误 |
| 界面 | Solid.js + Tailwind CSS | 包体积小，写法接近原生 HTML |
| 构建 | Vite + CRXJS | 快，且能正确处理扩展的 manifest |
| 扩展规范 | Manifest V3 | Chrome 当前要求的标准 |
| 本地存储 | IndexedDB（经 `idb`）+ `chrome.storage.local` | 大数据和小状态分开存 |
| 加密 | Web Crypto API（AES-GCM + PBKDF2） | 浏览器原生，无第三方依赖 |
| 测试 | Vitest | 102 个用例，含两台设备端到端仿真 |

## 开发

```bash
npm install
npm run dev         # 开发模式（带热更新）
npm run typecheck   # 类型检查
npm test            # 跑测试（约 1 秒）
npm run build       # 生产构建 → dist/
```

细节见 [开发调试指南](docs/06-开发调试指南.md)。

### 项目结构

```
src/
├── core/         纯逻辑：数据类型、合并算法（不碰浏览器 API，可单元测试）
├── platform/     浏览器 API 的包装：书签读写、存储、消息
├── features/     具体功能：设置、Token、Gist、同步服务、历史
├── background/   后台（Service Worker）：接线与消息路由
├── ui/           界面：popup（小弹窗）+ options（独立设置页）
└── manifest.ts   扩展清单
tests/            单元测试 + 两台设备端到端同步仿真
docs/             文档
```
