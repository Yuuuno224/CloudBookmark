# 05 · 界面怎么读（写给只会 HTML/CSS/JS 的人）

如果你能看懂下面这段，这篇文档就是为你写的：

```html
<button id="sync" class="btn">立即同步</button>
<script>
  document.getElementById('sync').onclick = () => alert('同步中');
</script>
```

本项目的界面用的是 **Solid.js** 框架。别怕，它离原生写法很近。
这篇会把项目里出现的所有"看起来像魔法"的东西讲清楚。

---

## 1. 先认识 JSX / TSX

项目里界面文件的后缀是 `.tsx`。里面的代码长这样：

```tsx
<button
  class="rounded-md bg-blue-600 px-3 py-2 text-sm text-white"
  onClick={() => runSync()}
>
  立即同步
</button>
```

这**不是** HTML，而是 JavaScript 里写标签的一种语法（叫 JSX）。
编译之后它其实变成创建元素的函数调用。你可以先这样理解：

| HTML 里写的 | TSX 里写的 | 说明 |
|------------|-----------|------|
| `class="a b"` | `class="a b"` | 一样。注意 React 里要写 `className`，**Solid 不需要** |
| `onclick="fn()"` | `onClick={() => fn()}` | 事件名改成小驼峰，值是函数 |
| `style="height:50%"` | `style={{ height: '50%' }}` | 值是对象，注意两层花括号 |
| `<input value="x">` | `value={value()}` | 花括号里可以放任意 JS 表达式 |
| `disabled` | `disabled={busy()}` | 动态属性 |

花括号 `{}` 的含义是"这里放 JavaScript"：

```tsx
<p>本地 {count()} 条</p>              {/* 显示变量的值 */}
<p>{loading() ? '加载中…' : '完成'}</p> {/* 三元表达式 */}
<div>{items().map((item) => <li>{item}</li>)}</div>  {/* 循环 */}
```

> **和模板字符串的区别**：`{` 里不能写 `if` / `for` 这种语句，
> 只能写表达式。要条件渲染用 `<Show>`，要循环用 `<For>`（下面讲）。

## 2. Solid 的核心：signal（信号）

原生 JS 里，你改了一个变量，界面不会自动更新，得手动操作 DOM：

```js
let count = 0;
count = 1;
document.getElementById('n').textContent = count;  // 必须手动同步
```

Solid 里用 **signal** 表示"会变的值"：

```tsx
import { createSignal } from 'solid-js';

const [count, setCount] = createSignal(0);   // 定义
count();                                      // 读（注意：要加括号！）
setCount(5);                                  // 写
```

在界面上用到 `count()` 的地方，**值一变，那一小块会自动重画**，
不需要你手动碰 DOM。

### 为什么读的时候要加括号 `()`？

因为 `count` 本身是一个函数，调用它才拿到当前值。
这是 Solid 和你以前写的 JS 最大的区别，也是最容易忘的一点：**忘记加括号会显示函数本身**。

项目里的例子（`src/ui/popup/App.tsx`）：

```tsx
const { state, ready } = useLiveState();   // state 是一个 signal

// 读的时候：
<p>{state().entryCount} 条</p>
// 而不是 {state.entryCount}
```

### 常用的几个

| 写法 | 作用 | 项目里的例子 |
|------|------|-------------|
| `createSignal(初始值)` | 定义一个会变的值 | `const [busy, setBusy] = createSignal(false)` |
| `createMemo(() => 表达式)` | 由别的值算出来的值，会自动跟着更新 | `const allDecided = createMemo(() => decided() >= conflicts().length)` |
| `onMount(fn)` | 组件第一次显示出来时执行一次 | 打开页面时去后台取数据 |
| `onCleanup(fn)` | 组件被移除时执行，用来解除订阅 | 取消 `chrome.storage.onChanged` 监听 |

## 3. 两个控制流程组件：`Show` 和 `For`

它们相当于"if"和"for"，但是写在标签里。

### `Show` = if

```tsx
<Show when={state().conflictCount > 0}>
  <p>有冲突需要处理</p>
</Show>
```

带 `fallback` 就是"否则"：

```tsx
<Show when={loading()} fallback={<p>加载完了</p>}>
  <p>正在加载…</p>
</Show>
```

`Show` 还有个很有用的写法：`when` 的值可能为 `null` 时，
用回调形式拿"非空版本"，这样就不用到处写 `!`：

```tsx
<Show when={env().hasToken}>
  {(has) => <span>已配置：{has()}</span>}   {/* has() 一定是 true */}
</Show>
```

项目里 `src/ui/popup/App.tsx` 里的这段就是这个用法：

```tsx
<Show when={outcome()}>
  {(result) => (
    <Show when={!result().needsConfirm}>
      <Card title="本次同步结果">…</Card>
    </Show>
  )}
</Show>
```

### `For` = for

```tsx
<For each={conflicts()}>
  {(conflict, index) => (
    <div>第 {index() + 1} 项：{conflict.label}</div>
  )}
</For>
```

`For` 会很聪明地只更新变化的那几条，而不是全部重建。

> 小提醒：`.map()` 也能渲染数组，项目里两种都用到了。
> 数据量小的时候用 `.map()` 更顺眼，需要按 key 复用时用 `<For>`。

## 4. 组件 = 返回标签的函数

`src/ui/shared/components.tsx` 里的 `Card`：

```tsx
export function Card(props: {
  title?: string;
  children: JSX.Element;
}) {
  return (
    <section class="rounded-lg border border-slate-200 bg-white">
      <Show when={props.title}>
        <h2>{props.title}</h2>
      </Show>
      <div>{props.children}</div>
    </section>
  );
}
```

用法：

```tsx
<Card title="云端文件">
  <p>这里的内容会出现在 children 的位置</p>
</Card>
```

要点：

- 组件就是一个**首字母大写的函数**，返回一段标签
- 它的输入叫 `props`，用 `props.xxx` 读
- `<Card>…</Card>` 标签之间的内容会传进 `props.children`
- **不要解构 props**（不要写 `const { title } = props`），
  那样会丢掉"响应式更新"的能力。永远写 `props.title`

### 那些类型标注

```tsx
props: { title?: string; children: JSX.Element }
```

- `?` 表示这个属性可以不传
- `string` 是字符串
- `JSX.Element` 表示"一段界面内容"
- 这是 TypeScript 的类型检查，写错了编辑器会立刻标红，**运行时会消失**，
  不影响性能

## 5. 项目里的状态是怎么流动的

记住一句话：**界面不存业务状态，只照镜子。**

```
   后台 Service Worker
        │ 写入
        ▼
   chrome.storage.local  (settings / syncState)
        │ 触发 onChanged 事件
        ▼
   src/ui/shared/useStore.ts  →  useLiveState()
        │ 把值放进 signal
        ▼
   界面组件自动重画
```

`useLiveState()` 的完整实现（`src/ui/shared/useStore.ts`）：

```ts
export function useLiveState() {
  const [state, setState] = createSignal(defaultSyncState());
  const [settings, setSettings] = createSignal(DEFAULT_SETTINGS);

  onMount(() => {
    // 1. 先读一次当前值
    void (async () => {
      const stored = await kvStore.getMany(['syncState', 'settings']);
      setState({ ...defaultSyncState(), ...(stored.syncState ?? {}) });
    })();

    // 2. 订阅变化，以后后台一改这里就会自动更新
    const off = kvStore.onChange((changed) => {
      if (changed.syncState) setState({ ...defaultSyncState(), ...changed.syncState });
    });

    // 3. 组件消失时取消订阅，避免内存泄漏
    onCleanup(off);
  });

  return { state, settings, ready };
}
```

**加一个新的后台状态字段**要动三个地方：`src/core/types.ts` 加字段、
`src/platform/kv.ts` 确保它在 `syncState` 里、界面上直接 `state().新字段`。

### 界面向后台下指令：`sendRequest`

```ts
const result = await sendRequest({ type: 'sync:run', mode: 'merge' });
```

这句话会通过 `chrome.runtime.sendMessage` 把请求发给后台，
后台处理完把结果传回来。类型是自动推导的：写成 `type: 'sync:run'`，
返回值的类型就是 `SyncOutcome`，写错参数编辑器会报错。

好处是**你不需要记后台有哪些接口**：在 `src/platform/messaging.ts` 里
看 `Request` 那个类型，所有接口一目了然。

如果后台报错，`sendRequest` 会直接 `throw`，所以用 `try / catch` 或者
项目提供的 `useAction().run()`（它会自动把错误显示到界面上）：

```ts
const action = useAction();

<Button onClick={() => action.run(() => sendRequest({ type: 'sync:run', mode: 'merge' }))}>
  立即同步
</Button>

<Show when={action.error()}>
  <Banner tone="danger">{action.error()}</Banner>
</Show>
```

## 6. 那些 class 名是怎么回事（Tailwind CSS）

项目里没有单独的 `.css` 文件写样式，而是把样式写成 class：

```tsx
<div class="rounded-md border border-slate-200 bg-white px-3 py-2 text-sm">
```

这是 **Tailwind CSS** 的用法，每个 class 只做一件小事：

| class | 含义 |
|-------|------|
| `rounded-md` | 圆角（中等） |
| `border` | 有边框 |
| `border-slate-200` | 边框颜色（浅灰） |
| `bg-white` / `bg-blue-600` | 背景色 |
| `text-sm` / `text-slate-600` | 字号 / 文字颜色 |
| `px-3 py-2` | 左右内边距 3 单位 / 上下内边距 2 单位 |
| `mt-2` / `mb-1` | 上/下外边距 |
| `flex` / `items-center` / `justify-between` | 弹性布局 |
| `grid grid-cols-2 gap-2` | 两列网格 |
| `hover:bg-slate-50` | 鼠标悬停时的背景色 |
| `disabled:opacity-50` | 禁用时的透明度 |
| `truncate` | 太长就显示省略号 |
| `break-words` | 长单词换行而不是撑破容器 |

数字是"间距刻度"，1 = 0.25rem = 4px。所以 `px-3` = 左右各 12px。

想查某个 class 什么意思，直接搜 "tailwind + class 名" 就有官方文档。
也可以在浏览器里按 F12 改 class 试效果，改到满意再写回代码。

### 动态切换 class 的写法

条件不同、class 不同时用 `classList`：

```tsx
<button
  classList={{
    'px-3 py-1 rounded-md': true,        // 永远有的
    'bg-blue-600 text-white': active(),  // 条件为真才加
    'text-slate-600': !active(),
  }}
>
```

或者直接在字符串里用三元：

```tsx
<button class={`btn ${active() ? 'bg-blue-600' : 'bg-white'}`}>
```

两种项目里都有用，看哪种更清楚。

### 颜色和深色模式：为什么一个 `dark:` 都不用写

你翻遍界面代码也找不到 `dark:bg-slate-800` 这种写法。这不是漏了，
而是刻意换了一种更省事的方式：**语义化颜色**。

| 你会看到的写法 | 意思 |
|---------------|------|
| `bg-surface` | 卡片 / 面板的背景色 |
| `bg-surface-sunken` | 页面最底层背景（衬托卡片） |
| `bg-surface-raised` | 次级背景：表头、输入框 |
| `text-ink` | 主要文字 |
| `text-ink-soft` | 次要文字 |
| `text-ink-faint` | 时间戳、辅助说明 |
| `border-line` | 边框、分隔线 |
| `bg-brand` / `text-brand` | 主色（按钮、链接） |
| `bg-warn-soft` + `text-warn-ink` | 警告条的底色 + 文字色 |

这些名字背后是 CSS 变量，浅色和深色各一套，都写在 `src/ui/styles.css` 里：

```css
:root      { --cb-surface: #ffffff; --cb-ink: #1e293b; ... }  /* 浅色 */
:root.dark { --cb-surface: #1e293b; --cb-ink: #f1f5f9; ... }  /* 深色 */
```

Tailwind 再把它们注册成颜色名（`tailwind.config.js`），于是
`bg-surface` 编译出来就是 `background: var(--cb-surface)`。

**结果**：切换主题只是往 `<html>` 上换个类名，
所有颜色瞬间跟着变，组件一行都不用动。

**加一个新颜色**要改两个地方：

1. `src/ui/styles.css`：在 `:root` 和 `:root.dark` 里各加一个变量
2. `tailwind.config.js`：在 `theme.extend.colors` 里把它指向那个变量

**改配色**只改第 1 步就够了。

> 另外还有一个"语义色调"的概念（`src/ui/shared/tone.ts`）：
> 界面上所有带状态颜色的东西（圆点、徽章、提示条）只用五种语气
> ——`default / info / warn / danger / success`。
> 这样 `format.ts`（决定"现在是什么状态"）和 `components.tsx`（决定"这个状态画成什么颜色"）
> 之间就不需要互相认识，改配色也不会漏掉某个角落。

## 7. 改界面时的常见任务

### 加一个按钮

```tsx
<Button variant="primary" onClick={() => doSomething()}>
  按钮文字
</Button>
```

`variant` 可选：`primary`（蓝）、`secondary`（白底描边，默认）、
`danger`（红）、`success`（绿）、`ghost`（无底色）。`size` 可选 `sm` / `md`。
`loading` 为真时会自动显示转圈并禁用点击。

### 加一个标签页

1. 在 `src/ui/options/tabs/` 新建 `FooTab.tsx`，导出一个 `FooTab` 组件
2. 在 `src/ui/options/tabs/nav.ts` 的 `TabKey` 和 `TAB_LABELS` 里各加一项
3. 在 `src/ui/options/App.tsx` 里 import 并加一段 `<Show when={tab() === 'foo'}><FooTab /></Show>`

TypeScript 会在你漏改某处时报错，跟着提示走就行。

### 加一个后台接口

1. `src/platform/messaging.ts` 的 `Request` 联合类型里加一行，并在 `ResponseMap` 里写明返回类型
2. `src/background/handlers.ts` 的 `switch` 里加一个 `case`
3. 界面里 `sendRequest({ type: '你的类型', ... })`

如果漏了第 2 步，编译时会报错（`const exhaustive: never` 那个技巧）。

### 改提示文案

界面上的中文都集中在两个地方：

- `src/ui/shared/format.ts` —— 时间、动作名、"已同步/同步中"这类状态文案
- 各个标签页文件里 —— 具体的说明文字

## 8. 不要做的事

| 别这么做 | 原因 |
|---------|------|
| `const { title } = props` | 会丢掉响应式，属性变了界面不更新 |
| 忘记 `()`：`state.entryCount` | 显示出来会是函数本身，不是值 |
| 用 `if` / `for` 语句写在标签里 | `{}` 里只能放表达式，用 `<Show>` / `<For>` |
| 在界面上直接 `chrome.bookmarks` 改书签 | 界面只发指令；直接改会让变更记录和同步状态错乱 |
| 在界面上直接操作 IndexedDB | 同上，后台是唯一的数据所有者 |
| 把状态存在模块级变量里 | 弹窗一关就没了；要放 `chrome.storage` |
