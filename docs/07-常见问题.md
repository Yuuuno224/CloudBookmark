# 07 · 常见问题与故障排查

按"你遇到的现象"查找。每条都写了**原因**和**怎么办**。

---

## 一、安装与配置

### 两种授权方式该选哪个？

| | 方式一：填 Token | 方式二：用 GitHub 账号授权 |
|---|---|---|
| 需要准备什么 | 去 GitHub 生成一个 Token | 去 GitHub 建一个 OAuth App（免费，一分钟） |
| 操作起来 | 复制粘贴一长串字符，容易漏字符 | 填一个 8 位短码，不用复制长字符串 |
| 权限 | 只有 `gist` | 只有 `gist` |
| 存哪 | 加密后存本机 | 加密后存本机 |

**只在一台设备上用、图省事 → 方式一。** 要在好几台设备之间同步、
经常嫌 Token 太长容易贴错 → 方式二。

### 方式二提示「这个 OAuth App 没有启用 Device Flow」

- **原因**：创建 OAuth App 时没有勾选 **Enable Device Flow**。
- **怎么办**：打开 [github.com/settings/developers](https://github.com/settings/developers)
  → 点开你的 App → 勾选 **Enable Device Flow** → 保存，然后回到扩展重新点「开始授权」。

### 方式二提示「client_id 不正确」

复制 Client ID 时漏字符了。它形如 `Iv1.0123456789abcdef`，
在 OAuth App 的详情页上（不是 client secret，别复制错）。

### 为什么方式二要我自己建一个 OAuth App？

因为常见的「点按钮跳转授权」在纯前端扩展里走不通：那一步需要用
`client_secret` 去换 access_token，而扩展的代码是公开的，藏不住任何密钥。

GitHub 的**设备流程**是专门为没有后端的客户端（命令行工具之类）设计的：
换 token 只需要公开的 `client_id`，**不需要密钥**。但 client_id 只有注册
这个 App 的人能拿到，所以需要你自己花一分钟建一个。

> 理论上这个项目的作者可以注册一个共用的 OAuth App 并把 client_id 内置进去，
> 那样所有人都能省掉这一步。如果你希望这样，可以去提一个 issue。

### 提示「这个授权会在 8 小时后失效」

- **原因**：你建的那个 OAuth App 开启了 **Expiring user tokens**
  （access token 只有 8 小时有效期）。
- **怎么办**：到 OAuth App 设置里把这一项关掉。否则书签同步每 8 小时就会掉线一次，
  需要重新授权。
- 关掉之后重新授权一次即可。

### 装了扩展但图标是灰的 / 点开什么都没有

- **原因**：还没配置 GitHub Token。
- **怎么办**：点图标 → 设置 → 填 Token。徽章上显示 `!` 说明上次同步出错，
  鼠标悬停在图标上能看到具体原因。

### 提示「这个 Token 没有 gist 权限」

- **原因**：创建 Token 时没勾 `gist`。
- **怎么办**：
  - **经典 Token**（`ghp_` 开头）：重新生成，勾选 `gist`
  - **细粒度 Token**（`github_pat_` 开头）：Permissions → Account permissions
    → **Gists** → 选 **Read and write**
  - 另外注意：细粒度 Token 还要在 "Resource owner" 里选对账号，
    并且如果组织启用了 SSO，需要点 Authorize

### 提示「Token 无效或已被撤销」

- Token 被你在 GitHub 上删掉了、或者过期了。重新生成一个。
- 也有可能是复制时带了空格或换行——输入框会自动去掉首尾空格，
  但中间如果有断行就会失败。重新复制一次，注意复制完整。

### 设置页显示"已配置"，但同步提示「还没有配置 GitHub Token」

- **原因**：Token 解密失败。通常发生在"重装扩展"或"换了浏览器配置文件"之后
  （加密密钥里包含扩展 id，重装后 id 变了）。
- **怎么办**：重新粘贴一次 Token。

### 怎么撤销授权 / 换一个 GitHub 账号？

- **方式一（Token）**：到 GitHub → Settings → Developer settings →
  Personal access tokens 里删掉那个 Token；在扩展设置页点「移除本机保存的凭据」，
  再填新的。
- **方式二（GitHub 授权）**：到
  [Settings → Applications → Authorized OAuth Apps](https://github.com/settings/applications)
  里点 Revoke；扩展设置页也有一个「在 GitHub 上查看 / 撤销已授权的应用」链接。
  然后在扩展里点「移除本机保存的凭据」，重新授权。

两边的顺序都无所谓，但**两边都清理干净**才算是真的撤销。

### 界面太刺眼 / 想要深色模式

- 弹窗和设置页的**右上角有个太阳 / 月亮图标**，点一下就在浅色和深色之间切换。
- 想让它跟着系统走：设置页 →「外观」→ 选 **跟随系统**。
- 三个选项：跟随系统 / 浅色 / 深色，切换是即时的，只影响配色，不影响任何数据。

### 界面颜色有点不对（切换主题后）

主题是存在 `chrome.storage.local` 里的，界面打开时会先读一次。
如果你在两个窗口里同时改主题，可能需要重新打开那个窗口才会同步过来。

## 二、同步结果

### 书签变多了（出现重复）

**什么时候会发生：**

1. 第一次在新设备上同步时（旧版本必现，新版本已按网址自动配对）
2. 同一个网址在一边出现了两次以上 —— 这时扩展**故意不猜**，
   因为猜错会把两条不同的书签粘在一起

**怎么办：**

- 打开设置页 →「数据」→「扫描重复书签」→ 每组保留第一条，清理掉多余的
- 想避免以后再发生：确认所有设备都指向**同一个 Gist**（设置页能看到 Gist id）

### 删掉的书签又回来了

**原因**：另一台设备在删除传播过去之前，自己改了这本书签（或者那条书签
本来就在它那边存在且比你的删除更晚同步）。这会被判定为
"一边删、一边改"的冲突，而**默认行为是保住被修改的那一份**（删除不可逆，
宁可多留）。

**怎么办：**

- 想真的删掉：到「冲突」标签页，选「确认删除」
- 想避免：在删除的那台设备上**先同步一次**，再到另一台设备同步

### 提示「有 N 处冲突等待处理」，同步不往下走了

**这是正常的、也是刻意的行为**：宁可停下来问你，也不猜。
你的书签此刻**没有被改动过任何一条**。

**怎么办：**

- 去「冲突」标签页，每一处都会列出"上次同步时 / 本地现在 / 云端现在"三列，
  选完点「应用选择」
- 不确定就点「放弃处理」，什么都不会变，下次同步还会再问你
- 嫌烦的话：设置页 →「冲突策略」改成"自动保留本地"或"自动使用云端"

### 点「应用选择」提示「本地书签在等待处理期间又变化了」

**原因**：那份合并结果是基于**当时**的本地状态算出来的。你在处理冲突期间
又改了书签，硬套上去会覆盖掉你刚做的改动，所以扩展拒绝执行。

**怎么办**：重新点一次「立即同步」，会基于最新状态重新算冲突，再处理即可。

### 提示「已触发 GitHub 接口次数限制」

**原因**：GitHub 对接口调用有每小时上限（认证用户 5000 次/小时）。

**怎么办**：

- 等提示里说的时间过去（通常几分钟到一小时）
- 把自动同步间隔调大（设置页 →「自动同步」；默认 15 分钟已经很宽裕）
- 关掉「本地书签变化后自动同步」，改成手动

### 提示「书签数据太大，GitHub 拒绝了这次上传」

**原因**：Gist 单个文件有大小限制。

**怎么办：**

- 「数据」→ 清理重复书签
- 减少书签数量，或把不常用的书签（比如收藏夹里几千条链接）先导出备份再删掉
- 导出一份 JSON 存本地，这是最可靠的备份

### 提示「远端文件不是合法的 JSON，可能被手工改坏了」

**原因**：有人（也许是你）手工编辑过 Gist 里的 `cloudbookmark.json`，
把 JSON 语法弄坏了。

**怎么办**：

1. 打开那个 Gist，看 GitHub 的版本历史（Revisions），找到之前正常的版本
2. 复制它的内容，粘回文件里，提交
3. 或者干脆「设置」→「忘记当前 Gist」，扩展下次会新建一个空的 Gist，
   再把本地书签上传上去

### 同步成功但「云端无需更新」

正常。说明两边内容本来就一致，扩展**故意不产生一次无意义的提交**，
这是为了省 GitHub 接口次数。判断依据是内容指纹，时间戳变化不会触发上传。

## 三、需要"重来一次"的时候

### 我在 Gist 里手动改了书签，想让扩展重新认识它

手动改是**会被当成一次正常的云端修改**参与合并的——这正是数据自主的好处。
只要 JSON 语法合法就行。改完在任意设备上同步即可。

### 「忘记当前 Gist」会删掉 GitHub 上的文件吗？

**不会。** 它只是让扩展不再记住那个 Gist 的 id。
下次同步会去 Gist 列表里重新找；找不到（比如你把它删了）就新建一个空的。

如果你确实想彻底重来：

1. 「数据」→ 导出 JSON（先备份！）
2. 「设置」→ 忘记当前 Gist
3. 到 GitHub 上把旧的 Gist 删掉
4. 回到扩展点一次「立即同步」，它会新建一个 Gist 并把本地书签传上去

### 「清空本地缓存」会删我的书签吗？

**不会。** 它只删扩展自己的记录（同步基准 base、身份表 uidmap、备份、历史日志）。
书签和云端文件都不动。

**但是**：清空之后，下次同步会被当成"第一次同步"。
如果你的书签在两边都有，会靠网址重新配对一次；配对不上的可能产生重复。

### 我想完全重置

1. 「数据」→ 导出 JSON
2. 卸装扩展（在 `chrome://extensions/` 里点移除）
3. 重新加载扩展、填 Token、点同步

## 四、技术性排查

### 怎么看到底发生了什么？

打开后台日志，这是唯一能看到"真相"的地方：

`chrome://extensions/` → CloudBookmark → 点「Service Worker」（服务工作线程）

失败原因、API 错误、每一步的状态变化都会打在这里。
参考 [06-开发调试指南](06-开发调试指南.md) 第 5 节。

### 怎么确认两台设备用的是同一个 Gist？

两边都打开设置页 →「设置」→「云端文件（Gist）」→ 对比 Gist id。
不一样就说明它们各存各的（不会互相覆盖，但也不会互相同步）。

### 怀疑身份表坏了（书签反复重复/删除）

「数据」→「清空本地缓存」→ 再同步一次。
扩展会按网址重新和云端配对一次，重建身份表。

### 时钟不准会出问题吗？

不会影响正确性。合并判断基于**内容比较**，不依赖时间戳。
时间戳只用于界面显示。

## 五、安全相关

### 我的书签会被上传到哪里？

只有一个地方：**你自己 GitHub 账号下的一个私有（secret）Gist**。
本项目没有任何服务器。代码里只会访问两个 GitHub 域名：
`api.github.com`（读写 Gist）和 `github.com`（仅用于 OAuth 授权时换 token），
manifest 里的 `host_permissions` 也只声明了这两个，不多要任何其它域名。

### 凭据存在哪里？安全吗？

无论用哪种授权方式，凭据的存放方式是一样的：

- **明文只在内存里**，浏览器后台一休眠就没了
- 落盘的是 AES-GCM 加密后的密文（`chrome.storage.local` 的 `tokenBlob`）

**但请理解这层加密的真实强度**：派生密钥的材料（扩展 id + 设备 id）
就存在同一台电脑上，所以它只能防止"别人随手打开扩展存储就看见明文"，
防不住能读你磁盘、能调试你浏览器的恶意软件。

**真正保护你的是权限最小化**：这个凭据只有 `gist` 权限，
就算泄露，别人也只能读写你的 Gist，动不了你的代码仓库。
所以授权时**只要 gist**，不要图省事多要权限。

### 想更安全怎么办？

- 定期在 GitHub 上重新生成 Token（设置页换一下即可）
- 用完扩展后「移除本机保存的凭据」，需要时再授权
- 给 GitHub 账号开启两步验证

## 六、还没有解决的问题 / 已知限制

| 限制 | 说明 |
|------|------|
| 没有实时推送 | Gist 没有推送能力，只能靠定时轮询（所以间隔最小 5 分钟） |
| GET 与 PATCH 之间有竞态窗口 | 极端情况下（两台设备在同一秒内上传）后写的一方会覆盖先写的。窗口只有几百毫秒，正常使用碰不到。每次覆盖前都会自动备份，可以在「数据」里回滚 |
| 扩展被完全卸载后本地记录会丢 | 云端数据还在，重装后同步即可恢复；但"上次同步基准"没了，会走一次首次同步配对 |
| 书签数量极大时需要留意体积 | 见 03 文档第 5 节 |
